# 개발 규칙

- Next.js 코드를 변경하기 전에 설치된 `node_modules/next/dist/docs/`에서 해당 페이지, 요청 처리, 캐시, 인증 문서를 읽는다. 기억에 의존해 이전 버전 API를 추가하지 않는다.
- 페이지와 요청 처리 파일은 업무 계산을 직접 복제하지 않는다. 주문·재고·가격·등록·이미지 규칙은 `src/lib`의 단일 경로를 호출한다.
- 관리자용 요청은 서버에서 관리자 역할을 검사하고 작업자용 요청은 작업자 역할과 배정 범위를 검사한다. 클라이언트 표시 여부만으로 접근을 제한한 변경은 허용하지 않는다.
- 데이터 구조 변경은 재현 가능한 마이그레이션으로 추가한다. 운영 요청 중 `CREATE TABLE`이나 `ALTER TABLE`을 실행하는 새 코드를 추가하지 않는다.
- 재고 수량과 재고 이동 이력, 주문 항목의 차감 표시는 하나의 원자적 작업으로 바꿔야 한다. 일부만 성공할 수 있는 변경은 허용하지 않는다.
- 외부 시스템 쓰기는 중복 요청에 안전해야 한다. 내부 작업 식별자와 외부 식별자를 저장하고 재시도 시 기존 결과를 확인한다.
- 비밀정보는 환경변수에서 읽고 서버 전용 코드 밖으로 전달하지 않는다. 새 환경변수는 `.env.example`에 의미와 유효 범위를 함께 추가한다.
- 외부 입력은 경계에서 검증하고 오류 응답은 `{ error: string }` 형태를 유지한다. 원본 외부 오류를 그대로 브라우저에 노출하지 않는다.
- 기능 변경은 `codex/<짧은-기능명>` 브랜치에서 수행하고 검증 뒤 `main`에 합친다. 긴급 복구를 제외하고 `main`에 직접 기능 커밋을 만들지 않는다.
- 한 커밋에는 한 기능 또는 한 수정 목적만 담는다. 문서·테스트는 그 목적을 검증하는 범위에서 같은 커밋에 포함하고, 서로 되돌려야 할 이유가 다른 변경을 섞지 않는다.
- 커밋 전 `npm test`, `npm run lint`, `npm run build`를 실행한다. 특정 명령을 실행하지 못했거나 실패했다면 성공으로 기록하지 말고 원인과 범위를 알린다.
- 생성 코드, `.env`, 로그, 로컬 휴대전화 설정, 빌드 결과, 대형 작업용 원본 파일을 커밋하지 않는다.
