# 시스템 구성

## 전체 흐름

브라우저의 관리자·작업자 화면은 서버 렌더링 페이지와 `/api` 요청을 통해 동작한다. 요청 처리는 세션에서 사용자를 확인한 뒤 `src/lib`의 업무 로직을 호출하고, 업무 로직은 PostgreSQL과 eBay·Shopify·Cloudflare R2를 사용한다. 포카마켓의 휴대전화 작업은 로컬 Windows 프로그램이 담당하며, 배포된 서버와 제한된 작업 메시지만 교환한다.

대표 주문 흐름은 `eBay 주문 조회 → 주문·항목 저장 → SKU 또는 수동 상품 연결 → 재고 확인 → 관리자 차감 지시 → 재고 수량과 이동 이력 저장 → 배송 정보 eBay 전송`이다. 포카마켓 조달은 재고 부족이 확인된 주문에서만 별도 요청되고, 로컬 휴대전화 작업자가 가격 한도를 확인한 뒤 결제 인증 단계에서 사람에게 제어를 넘긴다.

대표 이미지 흐름은 `원본 이미지/R2 → 이미지 작업 생성 → 로컬 또는 브라우저 처리 → 미리보기 저장 → 작업자 검토 → 관리자 또는 허용된 검토자의 승인 → 상품 이미지 교체와 이력 저장`이다. 처리 결과가 원본을 자동으로 대체해서는 안 된다.

## 구성 요소

- `src/app`: 관리자·작업자 화면과 HTTP 요청 진입점이다. 업무 규칙을 자체 구현하지 않고 `src/lib`에 위임한다.
- `src/lib`: 주문, 상품, 재고, 등록 초안, 이미지, 외부 판매 채널의 업무 로직을 소유한다. 데이터 저장과 외부 호출의 순서를 통제한다.
- `prisma`: PostgreSQL의 영구 데이터 구조와 배포 가능한 변경 이력을 소유한다.
- `scripts`: 서버 밖에서 실행되는 포카마켓 휴대전화 연결, 이미지 특징 생성, 관리자 초기화 작업을 소유한다.
- `tests`: 외부 네트워크 없이 핵심 계산·검증·중복 방지를 확인한다.

## 외부 경계

- eBay: OAuth 계정, 주문, 배송 처리, 상품·정책·광고 정보를 주고받는다. eBay 원본 응답은 진단을 위해 저장되지만 내부 사용자 외에는 공개하지 않는다.
- Shopify: 내부 상품을 판매 채널에 게시하고 외부 식별자와 실패 상태를 내부 상품에 기록한다.
- 포카마켓: 시세·판매 가능 상품을 가져오고, 내부 재고가 부족한 eBay 주문에 대해 관리자가 구매를 지시할 수 있다. 포카마켓은 내부 재고의 소유권 기록을 직접 변경하지 않는다.
- Cloudflare R2: 상품 사진, 가공 미리보기와 공개 가능한 이미지 자산을 저장한다. 계정·주문·인증정보는 저장하지 않는다.
- 로컬 AI/Android 작업자: 배포 서버에서 작업을 받아 처리 결과만 돌려준다. 세션 쿠키나 eBay 자격증명을 전달받지 않는다.
