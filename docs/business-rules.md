# 업무 규칙

## 상품과 재고

- 주문은 eBay와 Shopify 채널을 구분해 저장하며, 채널의 외부 주문 ID로 재수집 중복을 막는다.
- SKU는 판매 단위를 식별한다. eBay 주문 항목은 같은 SKU로 자동 연결할 수 있으며, 확실하지 않은 연결은 사람이 상품을 선택해 확정한다.
- 사람이 확정한 연결은 이후 자동 수집이나 유사도 결과보다 우선한다. 자동 처리로 사람의 연결을 덮어쓰면 안 된다.
- 내부 재고는 실제 보유 수량의 기준이다. 포카마켓에 판매 중인 상품이 있어도 구매가 완료되어 내부 입고 처리되기 전에는 내부 재고로 계산하지 않는다.
- 입고와 취소 복구는 수량을 더하고, 출고와 주문 차감은 수량을 뺀다. 조정은 입력값을 새 수량으로 사용한다. 모든 변경은 변경 전·후 수량과 사유를 이력으로 남긴다.
- 재고는 음수가 될 수 없다. 부족하면 차감을 건너뛰고 부족 상태를 표시한다.
- 한 주문 항목은 한 번만 차감한다. 이미 차감 표시가 있으면 주문을 다시 불러오거나 차감 버튼을 다시 눌러도 수량을 바꾸지 않는다.
- 취소 주문은 차감하지 않는다. 이미 차감한 주문이 취소되면 같은 수량을 복구하고 복구 이력을 남긴다.
- 배송 완료 주문도 아직 차감되지 않았다면 차감 대상이다. 취소 상태만 차감 대상에서 제외한다.

## 포카마켓 조달

- 판매채널 신규등록은 관리자가 재고 상품을 선택하고 eBay 또는 Shopify 상품 등록 확인을 누른 뒤에만 게시한다. 같은 그룹·앨범·버전으로 묶이는 카드는 옵션상품으로 자동 구성하고, 묶이지 않는 상품만 단품으로 등록한다. 옵션 썸네일은 없거나 구성이 바뀐 경우에만 자동 생성한다. 내부 재고가 없는 상품도 포카마켓에서 판매 중이라면 등록 후보가 될 수 있다.
- eBay에서 단품으로 판매 중인 카드가 옵션상품으로 전환되면 기존 단품을 철회한 뒤 같은 SKU를 옵션으로 게시한다. 옵션 게시가 실패하면 철회한 단품을 복구하고 내부 연결은 바꾸지 않는다. Shopify에서 같은 옵션 묶음이 여러 상품으로 나뉘어 있으면 하나의 대표 상품으로 합친 뒤 나머지 상품을 보관한다.
- eBay 주문 뒤 내부 재고가 부족하면 관리자가 포카마켓 구매를 명시적으로 요청한다. 시스템은 주문이 들어왔다는 이유만으로 구매를 시작하면 안 된다.
- 구매 요청은 배송 대기 중인 주문, 연결된 상품, 부족한 수량에 대해서만 만든다. 포카마켓 가격이 허용 한도를 넘거나 품절이면 자동 결제하지 않고 관리자 확인 대상으로 남긴다.
- 관리자는 주문이 없어도 재고관리 화면에서 상품과 수량을 명시해 휴대전화 구매를 요청할 수 있다. 별도의 보유재고 구매 분류나 자동 입고는 만들지 않으며, 실제 구매·수령 뒤 관리자가 재고를 직접 추가한다.
- 구매가 완료돼도 내부 재고를 자동 증가시키지 않는다. 실제 상품을 받은 뒤 입고 또는 재고 조정 이력을 남겨 반영한다.
- 결제 인증은 사람이 수행한다. 휴대전화 자동 조작은 상품 선택과 결제 직전까지 보조할 수 있지만 사람 확인을 우회할 수 없다.

## 가격 계산

판매채널 자동 반영은 관리자가 화면에서 채널(eBay·Shopify 통합 또는 개별)과 작업을 고르고 확인한 뒤에만 시작한다. 가격·수량 반영은 현재 연결된 판매중 상품을 대상으로 하며, 판매중단은 내부 재고와 포카마켓 매물이 모두 없는 상품만 대상으로 한다. Shopify 판매중단은 상품을 삭제하지 않고 보관(`ARCHIVED`) 상태로 전환한다.

가격 설정에는 포카마켓 상품가, 포카마켓 국내 배송비, 구매대행 비용, 원·달러 환율, 목표 마진율, eBay 판매수수료율, eBay 광고율, 국제 판매 수수료율, 주문당 고정비, 구매자에게 받는 배송비, 판매세 가산율, 등록수수료를 입력한다. 별도의 환율 변동 여유분은 넣지 않는다.

`원화 원가 = 포카마켓 상품가 + 국내 배송비 + 구매대행 비용`

`달러 원가 = 원화 원가 ÷ 적용 환율`

2026-09-18 확정(2026-09-21 반영): eBay는 상품값만이 아니라 배송비와 자기가 걷은 판매세에도 수수료를 매기고, 주문마다 고정비를 붙이며, 무료 등록 한도를 넘기면 등록할 때마다 돈을 받는다. 계산식은 이를 모두 반영한다.

`수수료율 = eBay 판매수수료율 + 국제 판매 수수료율 + 광고율`

`가산 = 1 + 판매세 가산율`

`고정비 = 구매자 배송비 × 가산 × 수수료율 + 주문당 고정비 + 등록수수료`

`권장 eBay 판매가 = (달러 원가 × (1 + 목표 마진율) + 고정비) ÷ (1 − 수수료율 × 가산)`

목표 마진율은 달러 원가에 대한 비율이다. 수수료율에 가산을 곱한 값이 100% 이상이면 계산을 거부한다. 환율이 없거나 0 이하인 경우, 비용 중 음수가 있는 경우에도 계산하지 않는다. 반올림 단위는 $0.10 올림이며 최소 판매가는 계산가보다 높을 때만 적용한다.

이 계산은 `src/lib/pricing.ts`의 `pricingInputsFromSettings`를 통해서만 설정을 읽는다. 호출부가 설정 항목을 손으로 나열하면 새 수수료 항목이 빠져 실제 판매가만 낮아진다. 2026-09-18~09-21 사이에 실제로 그 일이 있었고(등록·변동 경로가 국제수수료·주문당 고정비·배송비·판매세·등록수수료를 0으로 계산), 2026-09-21에 바로잡았다.

포카마켓 가격이 있으면 계산 결과를 eBay·Shopify의 판매가로 자동 사용한다. 포카마켓 가격이 없으면 관리자가 직접 입력한 판매가(USD)를 사용한다. 둘 다 있으면 포카마켓 계산가가 우선한다. 가격 검토 단계는 두지 않지만, 직접입력 USD 가격의 변경 이력은 보존한다. 판매채널 반영과 게시 자체는 관리자가 시작한다.

2026-09-10 확정: 두 가격이 모두 없으면 가격·수량 변동 작업에서 해당 판매 옵션의 수량을 0으로 만들어 가격 확인 전 판매를 보류한다. 내부 보유 재고와 묶음의 다른 옵션은 유지한다. 판매가격 입력 또는 포카마켓 가격 확보 후 변동 작업을 실행하면 정상 USD 가격과 판매 가능 수량을 반영하고 보류를 해제한다. 가격 보류는 상품 삭제·영구 종료와 구분하며, eBay는 Out-of-Stock 제어로 기존 GTC 리스팅을 유지하고 Shopify는 옵션별 PRICE_HOLD와 가격 확인 표식을 사용한다.

## 이미지

- 자동 매칭, 워터마크 제거, 배경·크기 조정 결과는 미리보기일 뿐이다. 사람이 승인해야 상품의 최종 이미지가 된다.
- 판매채널 등록 원본은 촬영본 연결 이미지 또는 사람이 승인한 이미지 작업 결과뿐이다. 후보 목록, 검수 전 결과, 이전 갤러리의 추가 이미지를 승인 결과에 자동으로 덧붙이면 안 된다.
- `워터마크 설정`은 eBay·Shopify·옵션 대표 썸네일이 공유한다. `image_source='lens_workbench'`이면 과거 촬영본보다 승인된 가공 결과 `imageUrl`을 원본으로 우선한다. 개별 업로드는 960×1200 캔버스 안에 원본 비율과 전체 가장자리를 보존해 배치한다. 촬영본은 흰 여백, 작업 완료 이미지는 저장된 배경·방향별 여백을 적용한다. 회전은 확장한 결과를 전체 포함하고 확대는 안전 여백 안에서만 적용한다. 음수 패딩은 사용하지 않는다. 사용자 요청에 따라 원본 짧은 변의 4.5% 반경으로 모서리를 둥글게 표시한다. 원본 파일은 보존한다. 가로 원본은 세로 방향으로 돌리고 비율을 유지해 공통 배치 상자에 전체 포함한다. 묶음 대표 이미지는 1000×1000이며 카드마다 전체 포함 방식으로 배치한다. 그림자는 사용하지 않는다. 미리보기 영역은 하나만 두며 서버 렌더가 완료되면 업로드에 쓰일 최종 이미지로 확정한다. 같은 원본·설정·렌더러 버전의 공용 R2 이미지 URL은 채널 구분 없이 재사용한다. 원본 파일은 덮어쓰지 않으며 기존 외부 갤러리는 별도 이미지 반영 작업이 완료되어야 변경된다.
- 외부 채널 API의 미디어 조회 결과와 구매자에게 실제 노출되는 공개 이미지는 구분한다. 공개 화면을 검증하지 않은 미디어를 `실제 게시 이미지`라고 확정하면 안 된다.
- 승인 전 원본 이미지와 이전 이미지 주소를 보존한다. 거절된 결과는 상품 이미지를 바꾸지 않는다.
- 작업자는 자신에게 배정된 이미지 작업만 처리한다. 상품 가격·재고·주문·판매 채널 정보는 이미지 작업에 필요하지 않다.
- 현재 최우선 품질 목표는 포카마켓 이미지의 워터마크를 카드 고유 무늬를 훼손하지 않고 제거하는 것이다. 제거 흔적, 글자 잔상, 카드 테두리 손상은 승인 실패 사유다.
- 포카마켓 사진 중에는 한 장에 카드 두 장이 대각선으로 담긴 것이 있다(앞뒤 또는 2장 세트). 이런 사진은 카드마다 따로 둥근 모서리를 만든다. 전체를 한 장으로 보고 바깥 테두리만 깎으면 각 카드의 모서리는 각진 채로 남고 맞닿은 두 모서리만 잘려 검은 카드에서는 흰 자국이 보인다. 배치를 확신할 수 없으면 둥글게 만들지 않는다. 잘못 깎는 것보다 그대로 두는 것이 낫다.
- 미통과로 돌린 카드도 자동 재처리를 기다리지 않고 그 자리에서 직접 고칠 수 있다. 구글렌즈로 다른 사진을 찾거나, 미통과 결과나 원본에서 카드 영역을 다시 잡는다. 저장하면 검수 대기로 올라와 사람이 다시 판정한다.
- AI 이미지 작업 화면에서 구글렌즈로 더 나은 사진을 찾아 검수 이미지를 교체할 수 있다. 찾은 사진은 그대로 쓰지 않고 카드 네 모서리를 찍어 카드만 잘라낸다. 바꾼 결과가 마음에 들지 않으면 AI가 만든 직전 결과로 되돌릴 수 있다. 사람이 고른 주소만 서버가 내려받아 같은 규격(540×860·카드별 라운드·흰 배경)으로 맞춘 뒤 검수 대기에 올린다. 상품 이미지 확정은 지금처럼 통과를 눌러야 이뤄지며, 이미 확정된 작업은 교체하지 않는다.
- AI 이미지 작업 화면은 앞으로 처리할 상품의 포카마켓 원본을 실제 처리 순서(대기열 작업 → 아직 담기지 않은 대상의 SKU 순서)대로 먼저 보여준다. 이 미리보기는 자동 처리 대상 조건과 같은 조건을 사용한다.
- AI 결과를 검수에서 통과시키면 그 카드는 곧바로 상품 이미지로 확정된다(사람이 통과를 누른 것이 곧 채택 확인이다). 확정에 실패하면 통과 상태로 남겨 두고 통과 목록의 일괄 업로드로 다시 시도한다. 이미 확정된 작업을 다시 올려도 같은 이미지를 그대로 돌려주며 새로 만들지 않는다.
- 관리자는 미리보기에서 상품을 AI 작업 대상에서 제외하거나, 급한 상품을 골라 대기열 맨 앞으로 올릴 수 있다.
- 관리자는 미리보기에서 상품을 AI 작업 대상에서 제외할 수 있다. 제외는 작업 행을 지우지 않고 `excluded` 상태로 남기므로, 대기열 추가와 자동 처리에서 계속 빠진다. 처리 중이거나 이미 승인된 작업은 제외하지 않는다. 제외 해제는 해당 상품을 다시 대기열로 되돌리고 공급이 없으면 기존 규칙대로 대기 상태로 내린다.

재고관리의 `등록 가능한 전체 등록`은 공급·이미지·가격 조건을 갖춘 미등록 상품을 한 번에 접수한다. 대상은 화면이 들고 있던 목록이 아니라 서버가 접수 시점에 같은 조건으로 다시 고른다. 한 번에 채널당 500개까지 접수하고 남은 수를 알려 주며, 실행 전에 등록 가능 수와 제외 사유(기존 연결·가격 미입력)를 사람에게 확인받는다.

변동처리 버튼은 가격·재고뿐 아니라 승인 이미지, 워터마크·배경 설정, 이미지 제작 버전 변경도 함께 반영한다. 묶음 이미지는 부모별 전체 옵션 단위로 처리하며 성공한 이미지 지문만 완료 이력으로 남긴다. 이미지 처리 실패가 가격·품절 반영을 막지 않도록 큐와 결과를 구분한다.


### 2026-09-14 조달 가격·수량 보호 (관리자 요청)
포카마켓 구매 허용가격은 기준가의 120%(원 단위 반올림)를 유지한다. 판매 목록에서 이 한도를 넘는 매물은 조달 수량에 합산하지 않는다. 기존 요청의 허용가격과 구매 완료 수량은 바꾸지 않는다.
조달 정보가 없거나 마지막 확인이 실패했거나 성공 후 24시간이 지나면 조달 판매 수량을 제외한다. 보유 재고는 그대로 유지하며, 보유 재고가 없는 경우 이전 직접입력 USD가 남아 있어도 오래된 조달 매물을 판매하지 않는다. 성공적인 재확인 후 변동에서 새 원가 기반 USD와 수량을 반영한다.
이번 관리자 요청에 따라 자동 최신화가 켜져 있으면 주문 상품→판매 중 조달 상품을 우선해 6시간 주기 목표로 순환한다. 실패 재시도 간격은 최소 15분이다. 5분마다 기존 연결 상품의 가격·수량 변동을 기존 채널 작업 큐에 예약하며 구매·신규등록·이미지 변경·보유재고 증감은 자동 실행하지 않는다. 자동 최신화 설정을 끄면 이 정기 예약도 중지된다. 판매채널 지연/장애 중에는 보류 대상 수와 실제 보류 완료 수를 구분한다.
