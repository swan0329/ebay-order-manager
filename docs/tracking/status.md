# 현재 상태

## 구현됨

- 관리자 로그인, 7일 세션, 관리자·이미지 작업자 역할 분리가 구현되어 있다. 전체 권한 경로에 대한 자동 검증은 완료되지 않았다.
- eBay OAuth, 주문 동기화, 주문 조회, 상품 연결, 배송 처리와 주문 내보내기가 구현되어 있고 관련 단위 테스트가 일부 존재한다.
- 상품 등록·수정·파일 가져오기, 내부 재고와 이동 이력, 주문별 중복 차감 방지가 구현되어 있으며 재고·상품 관련 테스트가 있다.
- eBay 상품 초안, 정책 동기화, 단건·파일 등록, 실패 재시도와 작업 기록이 구현되어 있고 서비스 단위 테스트가 일부 존재한다.
- R2 이미지 저장과 포토카드 이미지 매칭 경로가 구현되어 있고 관련 테스트가 일부 존재한다. CDN 캐시와 실제 운영 자격증명을 포함한 종단 검증은 완료되지 않았다.
- AI 이미지 작업·검토와 작업자 배정 경로가 구현 중이다. 작업자 결과는 별도 검수 이미지로 저장되고 관리자 승인 뒤에만 상품 이미지에 반영된다. 워터마크 잔상·카드 무늬 훼손·테두리 손상의 합성 고정 회귀 테스트가 추가됐지만 실제 반려 이미지 검증 세트는 아직 충분하지 않다.
- Shopify 상품 등록 경로는 자동검증 결과에 서명된 대상 스냅샷을 저장해 실제 실행 요청에서 전체 운영 목록을 다시 계산하지 않는다. 대량 작업은 전용 경량 상태 API에서 항목별 성공·실패를 갱신하고, 최대 2건만 병렬 처리한 뒤 배치 완료 시 전체 목록을 한 번 다시 계산한다. GraphQL 일시 오류는 제한 재시도하고 실패한 operation 이름과 Shopify 사유를 항목별로 표시한다. 서명·타입·빌드 자동 검증은 추가됐으며 실제 운영 게시의 종단 검증은 계속 필요하다.
- 포카마켓 기준가와 조달 가능 수량은 빠른구매 기준으로 수집한다(`CARD_DETAIL_COLLECTION` 모드, `https://phocamarket.com/card/v2/{pocamarket_id}`). 예전 `/sell` 목록은 1:1 거래 판매자 목록이라 우리가 살 수 없는 가격이었다. 이전 방식은 `POCAMARKET_RESPONSE_MODE=CARD_SELL_LIST`로 되돌릴 수 있다.
- 수집 기준을 바꾼 뒤에는 전체 최신화로 기준가를 다시 채우고, 가격/수량 변경 CSV로 eBay 판매가를 올려야 한다. 그 전까지 등록된 판매가는 1:1 최저가 기준이라 원가보다 낮다.
- 포카마켓 부족 재고 구매 연결과 Android 화면 자동 조작이 구현 중이다. 실제 결제는 사람 인증을 요구하지만 화면 변경·실패 복구·운영 안전성은 검증되지 않았다.
- 구매 작업은 PC에서 도는 브리지(`scripts/pocamarket-bridge.mjs`)가 가져가야만 대기 상태를 벗어난다. 브리지가 작업을 물어볼 때마다 `pocamarket_bridge_heartbeats`에 마지막 응답 시각을 남기고, 주문 화면은 그 시각으로 "PC 브리지 연결됨/꺼짐"을 보여 준다(`src/lib/pocamarket-bridge-status.ts`). 30초 넘게 응답이 없으면 꺼진 것으로 보며, 대기 중인 작업이 있는데 브리지가 꺼져 있으면 실행 방법을 화면에 안내한다. 브리지는 서버 응답 오류로 종료하지 않고 사유를 출력하며 계속 재시도한다.
- Android 11 이상의 무선 디버깅은 켤 때마다 포트가, DHCP로 IP가 바뀐다. 브리지는 설정 파일의 `adbAddress` 연결이 실패하면 USB 장치와 mDNS(`adb mdns services`)로 실제 주소를 찾아 붙고, 그래도 없으면 페어링 방법을 알려 준다. 무선 디버깅을 켜기만 해서는 붙지 않고 `adb pair`로 한 번 짝을 지어야 한다.
- 상품 운영 목록은 공급·이미지·eBay 상태를 조합해 판매 가능, 이미지 작업 필요, 재고보유 판매, 포카 조달판매, 판매중단 필요, 품절, 최신화 필요로 구분한다. 품절은 내부 재고와 포카마켓 매물이 모두 없는 최신화 완료 상품만 뜻한다.
- 옵션상품은 현재 카드 구성 해시와 R2 썸네일 상태를 저장하며, 선택한 묶음의 썸네일을 먼저 준비한 뒤 현재 구성과 일치할 때만 CSV를 생성한다. 신규 Add의 실제 eBay 업로드와 후속 Revise·옵션별 결과 확인은 아직 사람 검증이 필요하다.
- 신규등록 파일의 판매가는 `src/lib/listing-price.ts` 한 곳에서 정한다. 포카마켓 가격이 있으면 마진 계산가가 우선이고, 포카마켓 가격이 없는 상품만 사람이 입력한 eBay 판매가(USD)를 사용한다. 두 가격이 모두 없는 판매가능 상품은 "가격 미입력" 목록(`/products/price-missing`)에서 따로 입력한다.
- 옵션 추가 CSV는 그 묶음의 기존 활성 단품을 끝내는 End 행을 같은 파일에 함께 담는다. 단품 종료에는 그 단품의 상품번호와 SKU만 있으면 되고 부모 옵션상품의 상품번호는 필요 없으므로, 옵션 추가와 단품 종료 사이에 전체 활성상품 보고서를 다시 받을 필요가 없다. 아직 eBay에 없는 신규 묶음은 등록이 거부되면 단품만 사라지므로 기본으로 넣지 않고 사람이 켤 때만 넣는다(`src/lib/variation-listing-groups.ts`의 `variationSinglesToEnd`). End 행의 종료 사유는 단품 종료 CSV와 같은 값을 쓰도록 `src/lib/ebay-end-listing-csv.ts`의 `EBAY_END_LISTING_REASON` 한 곳에서 정한다.
- 업로드 뒤에는 eBay가 준 처리 결과 파일을 올려 부모 옵션상품의 상품번호를 확정한다(`/api/listing-upload/variation-groups/confirm-upload`). 전체 활성상품 보고서를 다시 받지 않고, eBay API도 호출하지 않는다(요청이 잦으면 판매 계정이 정지될 수 있다). 판매 종료 표시는 우리가 무엇을 요청했는지가 아니라 결과 파일에서 eBay가 End로 성공 처리했다고 알려 준 상품번호만 따르며, 실패한 행은 사유를 그대로 화면에 보여 준다. 결과 파일에 작업(Action) 열이 없으면 상품번호만 확정하고 종료 표시는 다음 전체 보고서에 맡긴다. 등록 성공이 확인됐는데 활성 단품이 남은 신규 묶음은 결과 화면에서 바로 종료 CSV를 받는다.
- eBay 활성상품 보고서 CSV/XLSX 가져오기, SKU·Item ID 연결, 미연결·중복·충돌 검토, 전체 보고서 기준 종료 확인이 구현되어 있다. 신규등록·가격/수량 변경·판매중단·연결검토 Excel을 목적별로 내려받으며 eBay 직접 쓰기는 수행하지 않는다.

## 남은 작업

1. 워터마크 제거 품질을 개선하고 고정 검증 이미지와 사람 승인 기준으로 회귀를 측정한다.
2. 포카마켓의 상품번호·가격·판매 상태를 본인 기기에서 안전하게 수집하고 변경 이력을 표시한다. 서비스 이용 조건과 계정 보안을 먼저 확인한다.
3. 목표 마진율, eBay 판매수수료율, 광고율, 포카마켓 국내 배송비, 구매대행비, 환율을 관리하는 설정 화면과 가격 계산을 구현한다.
4. 실제 eBay 활성상품 보고서 표본으로 열 호환성, 대량 가져오기 성능, 가격·수량 변경 및 판매중단 파일의 eBay 처리 결과를 종단 검증한다.
5. 포카마켓 구매·Shopify 게시·이미지 작업의 요청 중 데이터 구조 생성을 정식 데이터베이스 마이그레이션으로 통합한다.
6. 역할별 모든 화면과 API의 접근 테스트, 외부 쓰기 재시도와 중복 처리 테스트를 보강한다.
7. 10분 동안 5회 로그인 실패 시 15분 차단, 로그인 실패·권한 거부 감사 기록, 직원 계정 비활성화와 세션 무효화, 기기·작업 토큰 폐기 절차를 구현한다.

## 결정이 필요한 항목

- 권장 판매가의 반올림 단위와 최소 판매가
- 포카마켓 국내 배송비와 구매대행비가 주문 단위인지 카드 단위인지, 고정 금액인지 비율인지
- 운영 데이터의 보존 기간, 백업 주기와 복구 시험 절차

현재 작업 폴더에는 커밋되지 않은 기능과 수정이 광범위하게 존재한다. 구현 완료 판단은 현재 파일을 기준으로 했으며, 전체 검증 명령의 성공 여부는 아직 확인하지 않았다.
