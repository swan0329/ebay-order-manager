# 현재 상태

## 구현됨

- 관리자 로그인, 7일 세션, 관리자·이미지 작업자 역할 분리가 구현되어 있다. 전체 권한 경로에 대한 자동 검증은 완료되지 않았다.
- eBay OAuth, 주문 동기화, 주문 조회, 상품 연결, 배송 처리와 주문 내보내기가 구현되어 있고 관련 단위 테스트가 일부 존재한다.
- 상품 등록·수정·파일 가져오기, 내부 재고와 이동 이력, 주문별 중복 차감 방지가 구현되어 있으며 재고·상품 관련 테스트가 있다.
- eBay 상품 초안, 정책 동기화, 단건·파일 등록, 실패 재시도와 작업 기록이 구현되어 있고 서비스 단위 테스트가 일부 존재한다.
- R2 이미지 저장과 포토카드 이미지 매칭 경로가 구현되어 있고 관련 테스트가 일부 존재한다. CDN 캐시와 실제 운영 자격증명을 포함한 종단 검증은 완료되지 않았다.
- AI 이미지 작업·검토와 작업자 배정 경로가 구현 중이다. 작업자 결과는 별도 검수 이미지로 저장되고 관리자 승인 뒤에만 상품 이미지에 반영된다. 워터마크 잔상·카드 무늬 훼손·테두리 손상의 합성 고정 회귀 테스트가 추가됐지만 실제 반려 이미지 검증 세트는 아직 충분하지 않다.
- AI 이미지 작업 화면에 처리 예정 상품의 원본 사진 미리보기와 작업 제외·해제가 추가됐다. 예정 목록은 실제 처리 순서대로 48개씩 보여주고, 제외한 상품은 `ai_image_jobs.status='excluded'`로 남아 대기열 추가·자동 처리·상단 작업 필요 건수에서 빠진다. 처리 중·승인 완료 작업은 제외되지 않는다. 새 SQL은 실제 Postgres 엔진에서 순서·페이지·제외·해제·재담김 방지를 확인했다.
- Shopify 상품 등록·SKU 중복 복구·가격/재고 경량 반영, GraphQL 대표 이미지 안전 교체와 주문 수집 경로가 구현되어 있다. 주문은 채널·외부 주문 ID로 중복을 막고 라인아이템, 구매자 배송 정보, 금액, 결제·배송 상태와 송장을 저장한다. 취소 재수집 시 이미 차감된 재고는 이력과 항목 표시를 한 트랜잭션에서 복구한다. 실제 신규 상품은 GraphQL `productSet` 한 요청으로 이미지·가격·재고·카테고리를 함께 반영한다. 이미지 교체는 새 미디어가 준비된 뒤 기존 미디어를 정리하며 12초 안에 준비되지 않으면 기존 이미지를 유지한 채 실패한다. 실제 운영 Shopify 주문·게시 종단 검증은 아직 수행하지 않았다.
- eBay·Shopify 다건 등록은 DB 작업함에 먼저 접수하고 작업별 lease로 실행기 하나가 최대 3건씩 처리한다. 각 항목 완료 시 성공·실패 수를 즉시 증가시켜 화면의 진행 막대·현재 SKU·집계가 실시간 갱신된다. 작업 실행은 별도 cron 비밀값 없이 접수·조회 요청의 서버 내부 후속 작업으로 시작한다. 브라우저를 닫아도 작업이 이어지고 다시 열면 저장된 작업 ID로 진행률과 실패 SKU를 복구한다.
- eBay Feed 상태 조회는 별도 refresh lease와 비중첩 화면 폴링을 사용하며, 원문 결과 다운로드에는 25초 제한 시간을 적용한다.
- 포카마켓 부족 재고 구매 연결과 Android 화면 자동 조작이 구현 중이다. 실제 결제는 사람 인증을 요구하지만 화면 변경·실패 복구·운영 안전성은 검증되지 않았다.
- 상품 운영 목록은 공급·이미지·eBay 상태를 조합해 판매 가능, 이미지 작업 필요, 재고보유 판매, 포카 조달판매, 판매중단 필요, 품절, 최신화 필요로 구분한다. 품절은 내부 재고와 포카마켓 매물이 모두 없는 최신화 완료 상품만 뜻한다.
- 옵션상품은 현재 카드 구성 해시와 R2 썸네일 상태를 저장하며, 선택한 묶음의 썸네일을 먼저 준비한 뒤 현재 구성과 일치할 때만 CSV를 생성한다. 신규 Add의 실제 eBay 업로드와 후속 Revise·옵션별 결과 확인은 아직 사람 검증이 필요하다.
- 옵션 추가 CSV는 그 묶음의 기존 활성 단품을 끝내는 End 행을 같은 파일에 함께 담는다. 단품 종료에는 그 단품의 상품번호와 SKU만 있으면 되고 부모 옵션상품의 상품번호는 필요 없으므로, 옵션 추가와 단품 종료 사이에 전체 활성상품 보고서를 다시 받을 필요가 없다. 아직 eBay에 없는 신규 묶음은 등록이 거부되면 단품만 사라지므로 기본으로 넣지 않고 사람이 켤 때만 넣는다(`src/lib/variation-listing-groups.ts`의 `variationSinglesToEnd`).
- 레거시 CSV 업로드 뒤에는 eBay 처리 결과 파일로 부모 옵션상품 번호를 즉시 확정할 수 있다(`/api/listing-upload/variation-groups/confirm-upload`). Inventory API 등록 작업은 성공 뒤 활성 재고 보고서를 자동 예약하며, 시간별 예약 작업이 완료 파일을 내려받아 전체 현황을 다시 검증한다. 판매 종료 표시는 eBay 성공 결과나 이후 전체 활성상품 보고서처럼 외부에서 확인된 결과만 따른다.
- 신규등록 파일의 판매가는 `src/lib/listing-price.ts` 한 곳에서 정한다. 포카마켓 가격이 있으면 마진 계산가가 언제나 우선이고, 포카마켓에 없는 상품만 사람이 입력한 eBay 판매가(USD)를 쓴다. 두 가격이 모두 없는 판매가능 상품은 "가격 미입력" 목록(`/products/price-missing`)에서 따로 입력한다.
- eBay 활성상품 보고서는 Feed API로 자동 요청·다운로드하며 CSV/XLSX 수동 가져오기는 보조 수단으로 남아 있다. 옵션 SKU별 행 보존, SKU·Item ID 연결, 미연결·중복·충돌 검토, 전체 보고서 기준 종료 확인과 실제 eBay 가격·수량 기준값 갱신이 구현되어 있다. 신규등록은 관리자의 최종 확인 뒤 Inventory API로 처리하며 SKU/offer 선조회로 재시도 중복을 막는다. 가격·수량 변경과 판매중단은 확인 뒤 Feed API 작업으로 제출하고 결과를 자동 반영한다.
- 재고관리의 판매채널 자동 반영 영역은 eBay·Shopify별 등록 가능, 가격·수량 변경, 판매중단 필요 상품 수를 실제 실행 대상 조건으로 계산해 표시한다.
- Shopify 단품 업로더는 기존처럼 저장된 워터마크 포함 이미지를 그대로 게시한다. eBay API는 연결된 Shopify 상품이면 Shopify의 실제 게시 미디어 URL을 읽어 같은 이미지를 사용하고, 미연결 상품이면 Shopify와 동일한 저장 이미지 우선순위를 사용한다. 옵션 대표 썸네일의 로고·투명도·크기·간격은 별도 설정으로 저장한다. 상세·가격·수량은 공통 빌더를 사용한다.

## 남은 작업

1. 워터마크 제거 품질을 개선하고 고정 검증 이미지와 사람 승인 기준으로 회귀를 측정한다.
2. 포카마켓의 상품번호·가격·판매 상태를 본인 기기에서 안전하게 수집하고 변경 이력을 표시한다. 서비스 이용 조건과 계정 보안을 먼저 확인한다.
3. 목표 마진율, eBay 판매수수료율, 광고율, 포카마켓 국내 배송비, 구매대행비, 환율을 관리하는 설정 화면과 가격 계산을 구현한다.
4. 실제 eBay 활성상품 보고서 표본으로 열 호환성, 대량 가져오기 성능, 가격·수량 변경 및 판매중단 파일의 eBay 처리 결과를 종단 검증한다.
5. 포카마켓 구매·Shopify 게시·이미지 작업의 요청 중 데이터 구조 생성을 정식 데이터베이스 마이그레이션으로 통합한다.
6. 역할별 모든 화면과 API의 접근 테스트, 외부 쓰기 재시도와 중복 처리 테스트를 보강한다.
7. 10분 동안 5회 로그인 실패 시 15분 차단, 로그인 실패·권한 거부 감사 기록, 직원 계정 비활성화와 세션 무효화, 기기·작업 토큰 폐기 절차를 구현한다.

## 결정이 필요한 항목

- 권장 판매가의 반올림 단위와 최소 판매가
- 포카마켓 국내 배송비와 구매대행비가 주문 단위인지 카드 단위인지, 고정 금액인지 비율인지
- 운영 데이터의 보존 기간, 백업 주기와 복구 시험 절차

현재 작업 폴더에는 커밋되지 않은 기능과 수정이 광범위하게 존재한다. 현재 파일 기준 전체 테스트와 프로덕션 빌드는 통과했지만, 전체 린트는 기존 AI 이미지 컴포넌트의 React Hook 오류 4건 때문에 실패한다. Shopify 주문 변경 파일만 대상으로 한 린트는 통과했다.
