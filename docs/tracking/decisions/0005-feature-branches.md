# 기능별 브랜치와 목적별 커밋

## 배경

상품, 주문, 재고, 이미지, 외부 서비스가 한 저장소에 있고 현재 작업 폴더에도 광범위한 미커밋 변경이 있다. 기본 브랜치에서 여러 목적을 함께 수정하면 검토와 되돌리기가 어렵다.

## 결정

새 기능과 일반 수정은 `codex/<짧은-기능명>` 브랜치에서 진행하고 검증 뒤 `main`에 합친다. 한 커밋에는 한 기능 또는 한 수정 목적을 담으며 해당 테스트와 문서는 함께 포함할 수 있다. 긴급 복구만 영향 범위를 확인한 뒤 기본 브랜치 직접 변경을 허용한다.

## 고려한 대안

`main` 직접 작업은 빠르지만 미완성 기능 격리와 검토가 어렵다. 기능·수정·문서를 모두 별도 커밋으로 강제하면 작은 변경도 맥락이 분리된다. 사람마다 임의의 브랜치 이름을 쓰면 작업 출처와 목적을 찾기 어렵다.

## 결과

서로 다른 목적의 변경은 별도 브랜치나 커밋으로 나눈다. 이미 존재하는 사용자 변경을 새 작업에 섞거나 정리 목적으로 되돌리지 않는다. 병합 전 테스트·검사·빌드 결과를 확인한다.
